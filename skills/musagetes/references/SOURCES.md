# 检索与匹配

## 来源优先级

`TITLE`、`ARTIST`、`ALBUM` 及已有可信 `ALBUMARTIST` 按以下优先级处理，并遵守[元数据规则](METADATA.md)的覆盖条件：

1. 当前内嵌且不严重偏离的值。
2. MusicBrainz。
3. Apple Music / iTunes 对应地区商店。
4. 发行方、厂牌或艺人官方网站。
5. Discogs、AllMusic、VGMdb、维基百科、豆瓣音乐、Bangumi 等资料站。
6. Deezer、Bandcamp、Amazon、Last.fm、QQ 音乐、网易云音乐等平台。

外部来源用于验证、补缺、发行识别和冲突排查。其它缺失的白名单字段按来源可靠性补齐，无需先统一标题、艺人或专辑写法。

**每张进入写入流程的专辑必须同时查询 MusicBrainz 与 Apple Music / iTunes**（对应地区商店），并按下文的置信度门槛核对候选。任一侧暂时不可用时重试并记录；任一侧未能核对时，不降低另一侧的采用门槛。两侧都无法确认时继续查可靠来源，身份或必填项仍无法确定则 `REVIEW_REQUIRED`。

同一网络请求最多重试两次，并遵守服务端限流和 `Retry-After`；持续不可用时记录错误并转向其它可靠来源。查询连续两轮无新增线索时收束该查询路线；只有出现新的别名、目录号或其它具体证据才继续扩展，避免无界重试。来源地址、接口与词表需按执行时官方资料核验，不依赖历史运行缓存推定仍有效。

查证结束后的字段缺失按[白名单缺失例外](METADATA_WHITELIST.md#可靠信息缺失例外)判断；下文的必填项阻断不包括已符合该例外并记录原因的缺失，发行身份及来源采用门槛照常核验。

选填白名单字段（厂牌、目录号、UPC、ASIN、ISRC、ORIGINALRELEASEDATE、VERSION、Composer 等）在确认同一发行或同一录音后，**复合（合并补缺）MusicBrainz 与 iTunes 的可靠值**：一侧有、另一侧无则补上；两侧一致则写入；两侧冲突时按上表优先级取 MusicBrainz，不把不同年份、地区、版本或曲目表拼成一条记录。iTunes 的 `collectionId` 可作 `ASIN` 以外的发行识别辅助，仅当来源明确为 ASIN/UPC 时才写入对应键。

疑似或确认 Vocaloid 专辑时，可补充查询 [MikuDB](https://mikudb.moe/)，核对专辑名或别名、Release Date、Tracklist、Vocal(s)、Producer、Circles / Labels、Genre 及 Vocaloid 类型。该来源不自动覆盖当前可信值；仅将可靠且能映射到白名单语义的信息写入标签，其余只用于识别和核对。

## 名称与艺人检索及置信度门槛

MusicBrainz 与 Apple Music / iTunes 均从可信的**专辑名称与专辑艺人**提取查询词；`ALBUMARTIST` 缺失时，可用可靠的曲目艺人辅助查询，但查询词不构成新增专辑艺人标签的依据。

查询采用**核心词组合、逐步调整**：

1. **分词与清理。** 在查询副本中，按语言习惯对专辑标题和专辑艺人分词或提取有辨识度的词组；中文、日文等保留有意义的词组，不逐字拆分。将标点及装饰性特殊字符替换为空格，合并连续空白，保留有效文字和数字，避免直接删符号造成词语粘连；Apple 发行类型后缀按[元数据规则](METADATA.md)处理。
2. **精简组合。** 首轮仅组合少量专辑核心词与艺人核心词，不将完整标题、全部合作艺人、长副标题、年份、目录号等原始信息一次性堆入查询字段。支持独立字段时，专辑词与艺人词分别放入对应字段；其余信息保留用于候选核验或后续缩小范围。
3. **逐步调整。** 未命中或结果无关时，减少非核心词、替换关键词，或将专辑词与艺人词分开查询；别名、译名与罗马字仅在有可靠对应依据时尝试。候选过多时，再逐项加入卷号、版本、年份等区分信息，每轮只作少量调整并记录结果。

查询简化只用于发现候选；核验时仍使用完整原始名称、艺人名单及卷号、版本、现场或重制标识等区分信息。比对时可规范 Unicode、大小写、空白及不改变语义的标点差异，并按[元数据规则](METADATA.md)处理 Apple 发行类型后缀。查询与比对均在临时副本中进行，不回写标签，也不据此拆分艺人实体。

两侧候选分别核验，搜索排名、单一文本相似度或工具评分只用于筛选，不能直接视为发行身份的置信概率。

**自动采用候选信息的门槛为 `HIGH`（高置信度）**，须同时满足：

1. **名称与艺人均对应。** 专辑名主体及艺人实体分别一致，或存在已验证的别名关系；仅共享关键词、同名专辑或只匹配其中一项不足以通过。`Various Artists` 等泛称须用实际曲目艺人核对，固定组合仍按一个实体处理。
2. **曲目证据对应。** 至少核对 `min(3, 本地曲目数, 候选发行曲目数)` 首有代表性的音轨，多轨专辑尽量覆盖不同位置；标题、艺人、相对曲序及关键时长形成一对一对应。本地与候选音轨的绝对时长差默认不超过 `max(10 秒, 本地曲目时长 × 5%)`（取两者较大值）；缺少时长或超出容差时，须另有可靠录音标识或可核验的剪辑、静音差异依据，不能仅凭名称通过。
3. **发行证据支持。** 日期、厂牌及目录号、条码、介质或版本信息中，至少一项与本地证据或独立可靠来源相符；候选自身提供的多个字段不算交叉验证。已知年份、地区、版本、介质等差异须解释清楚，不以商店地区直接推定本地发行地区。
4. **所采用信息无未解歧义。** 在拟采用信息的层级（专辑身份、具体发行或单轨录音）能够可靠区分候选；不能区分具体版本时，只采用已确认的共有事实，保留版本专属字段待核对。置信度通过仅允许补缺，不放宽[元数据规则](METADATA.md)的覆盖条件。

未通过的候选只保留为检索线索，继续补充查询或依据，记录未命中、不可用、置信度不足或版本歧义的具体原因。仍无法确定的身份或必填字段标记 `REVIEW_REQUIRED`；已有可靠依据的部分继续按下文处理，不能因一侧低置信度候选而跳过整张专辑，也不能仅因本地多出特典曲而降低已确认部分的置信度。

每侧记录各轮查询词与结果、商店地区（如适用）、候选 URL 或发行 ID、名称与艺人对应依据、核对音轨与时长差、发行佐证、置信度判定及采用范围；低置信度结果不得用于补入标签或封面。

## 完整匹配与部分匹配

优先寻找完整匹配，但本地与平台曲目数不同不构成整张失败或放弃补全的理由。本地可能包含隐藏曲、特典曲、店铺特典、先行或附赠音轨等平台未收录内容。

1. **确认专辑身份。** 结合 Album、Album Artist、日期、封面、厂牌及多数共有曲目的标题、顺序和时长，判断是否属于同一专辑或发行家族；身份不明时标记 `REVIEW_REQUIRED`。
2. **逐轨一对一匹配。** 综合碟号、轨号、标题、艺人和时长，仅对证据充分的曲目建立对应关系。
3. **补全已匹配曲目。** 按[元数据规则](METADATA.md)保留可信标题、艺人和专辑值，用外部来源补充缺失的白名单字段，仅凭规定的强证据覆盖现有值。
4. **处理本地额外曲目。** 保留音轨及可信的曲目级元数据，补齐已可靠确定的专辑级元数据；不从相邻音轨复制标题、艺人等曲目信息，也不因此跳过整张专辑。
5. **单独查询额外曲目。** 可用其它可靠来源补全 Title、Artist、Composer 等；查不到时保留可信原值，不猜测。
6. **记录本地缺失曲目。** 平台多出的曲目仅列入报告，不创建占位音轨。
7. **按本地成品确定结构。** 按[介质排除规则](AUDIO.md#dvd-与-bd-碟排除与计数)先排除 DVD / BD；额外音乐曲目顺序明确时，Track/Disc 当前值及总数描述最终实际音乐集合；`TRACKTOTAL` 为该碟实际音乐轨数，`DISCTOTAL` 为实际保留的音乐碟数，不机械复制平台总数。
8. **错位后重新确认。** 首次不对应后，后续曲目须重新逐轨匹配，不得整体平移套用标签。

元数据适用层级：

| 层级 | 字段与边界 |
| --- | --- |
| 专辑级 | 适用且可靠的 Album、Album Artist、Release Date / Year、Country、Genre、封面；可靠时也可补 Original Release Date、Version、Label、Publisher、Catalog Number、UPC / ASIN 等发行字段 |
| 曲目级或作品级 | Title、Artist、Composer、Lyricist、Lyrics、古典乐演奏及乐章信息；不得因来源缺失从其它音轨臆造 |
| 本地结构 | Track / Disc 及总数，按[介质排除规则](AUDIO.md#dvd-与-bd-碟排除与计数)排除 DVD / BD 后的最终实际音乐集合确定 |

专辑身份或专辑级元数据存在未解冲突，或音轨缺失无法安全确定的必填曲目级元数据时，标记相应项 `REVIEW_REQUIRED`。仅有部分曲目未在平台找到对应项时记为 `PARTIAL_MATCH`，不视为失败。

不同来源仅用于确认共有事实、补缺及识别额外曲目；部分匹配也不得拼接不同年份、地区、重制版或其它版本的冲突数据。
