# 工作副本清理与恢复

本协议落实[清理内容条件](delivery.md#清理)，不改变[原始文件策略](execution.md#文件角色与可选产物)。自动去重只处理来源链明确、已被完整替代的工作或待复核副本；唯一音频、原始资料、未知成员和未通过适用校验的成品不进入删除清单。相同标题、时长、扩展名或目录名都不证明重复。

## 逐文件证据

在任何移动前，持久化带稳定事务 ID、文件 ID 的清理 manifest，记录角色、原路径、当前路径、SHA-256、隔离位置、成品逐项映射、清理原因和等价证据。保留原始文件登记表与授权范围引用；计划变化另存修订，不覆盖旧计划。

- 未改内容的副本使用完整文件 SHA-256 字节等价。
- 只改标签或封面的有损文件比较完整有序音频 packet；不能以容器哈希变化推定音频变化，也不能以时长接近代替 packet 等价。
- 无损转换或整轨分轨比较完整解码 PCM；分轨按已确认索引顺序连接，显式处理 pregap、采样边界及所有音频区间。总时长相近、输出数量正确或单个输出可解码均不能单独证明无遗漏。
- 保存命令、工具版本、退出结果、输入输出文件哈希、音频参数、区间覆盖、解码/packet 摘要和适用例外的证据。无法证明等价时保留副本并列具体缺口。

## 执行与中断恢复

同一事务一个执行者，每步先写操作意图，操作后核验实际文件并追加结果。此流程是专辑事务内部的清理步骤，不替换其阶段词表。

1. **准备**：完整发布与领域复核通过；manifest、输出映射、等价证据可读且一致。再核验当前指纹、链接及目标冲突。任何条目无依据则保留，不执行该条目的清理。
2. **隔离**：把获准副本原子、拒绝覆盖地迁入本事务独占隔离位置，保持同一文件系统；工具不能保证原子拒绝覆盖时停止该步。跨文件系统不能冒充原子移动，保留源直到另有经过验证的复制/恢复方案。原始文件不动，隔离副本仍可恢复。
3. **对账**：扫描实际源、隔离、成品，核对全部指纹与等价证据；更新恢复快照及最终报告候选，移除已发布重复项的旧待复核分类。保存通过核对的不可变快照、报告及其哈希和 manifest 绑定。任何快照、报告或清单检查失败均保留隔离副本；不得先删完再尝试修复 JSON。
4. **移除**：先持久化逐文件最终移除意图，再重检成品、隔离副本及对账证据，最后逐项移除隔离文件。每次立即追加实际结果。重跑按文件 ID 集合统计，不能按尝试次数累计“已删除”。
5. **收尾**：追加覆盖全部仍存文件的最终快照，再审计历史与报告；按[空目录规则](delivery.md#空目录)仅对已计划目录由深到浅 `rmdir`。目录失败记录为残留，不撤销已完成文件操作，也不修改账本伪造回滚。

中断后先读日志与当前文件：源在、隔离不在时核验准备状态；源不在、隔离在时从实际隔离状态续做；两者都在时复核归属与竞态；两者都不在时，仅已持久化移除意图且成品和对账证据仍有效才确认移除。其它缺失是异常，不是成功。未完成最终删除时可按清单恢复隔离副本，仍拒绝覆盖并记新操作；最终删除后不能仅恢复旧 JSON 来宣称源文件回来了。

## 只读清理审计

[cleanup-audit.py](../scripts/cleanup-audit.py) 对上述重复音频副本核对当前文件与证据绑定，不执行移动、删除、锁定或写记录：

```sh
python3 -B "$skill_dir/scripts/cleanup-audit.py" --root "$music_root" --input "$cleanup_manifest"
```

输入支持 `--input -` 从 stdin 读取，替代受保护状态路径使用可重复的 `--state-dir`。JSON 顶层仅含 `schema_version: 1`、非空 `originals` 和非空 `entries`。文件引用统一为 `{"path":"相对路径","sha256":"64 位小写 SHA-256"}`；originals 是本事务需保护的全部原始文件引用。entry 仅含：

| 字段 | 约束 |
| --- | --- |
| `id`、`role`、`reason` | 稳定唯一 ID、`working` 或 `review`、非空清理依据 |
| `source`、`quarantine` | 工作副本的文件引用；受保护状态目录内的独占隔离相对路径 |
| `outputs` | 非空有序成品文件引用数组，所有文件当前存在且未变；不能同时是任何条目的清理候选 |
| `equivalence` | 字节相同时 `{"method":"bytes"}`，仅一个输出；其它为 `{"method":"pcm或packets","evidence":文件引用}` |
| `stage` | 当前持久化步骤：`prepared`、`quarantined`、`audited`、`remove-intent` 或 `removed` |
| `audit` | 对账前为 null；通过后为 `{"binding":"计划摘要","snapshot":文件引用,"report":文件引用}` |

PCM/packet evidence 引用的 JSON 含 `method`、`source`、有序 `outputs`、`source_digest`、`output_digest` 及非空 `command`。两组文件引用须与 manifest 精确一致；完整有序音频流摘要是相等的 64 位小写 SHA-256。helper 检查引用文件的当前哈希和摘要等价，**不运行解码器或证明证据内容真实**；完整解码、区间覆盖、参数及命令成功由执行者按前述规则核验并保存。其它原始文件策略、非音频 sidecar 或缓存处置不属于该 helper 的接受范围。

`binding(entry)` 对除 `stage`、`audit` 外的完整条目，用 Python `json.dumps(sort_keys=True, ensure_ascii=True, separators=(',', ':'))` 的 UTF-8 字节取 SHA-256。对账 receipt 绑定不可变快照和报告候选，不引用后续将被改写的滚动报告；最终报告可另存新版本。

输出 `scope: cleanup_files_and_evidence_bindings_only`，逐项动作是 `QUARANTINE`、`RECONCILE`、`RECORD_REMOVE_INTENT`、`REMOVE_QUARANTINE`、`COMPLETE` 或带原因的 `REVIEW_REQUIRED`；`removed_ids` 为已确认移除的唯一 ID 集合，可重复审计但不可累计求和。`ok: false` 时先排除错误、重新审计，不直接消费动作；`ok: true` 也不是清理授权或并发安全保证，执行瞬间仍重检。退出码 0 为当前审计通过、1 为文件/计划不一致、2 为输入或读取错误；通过不代表清理已经完成。
