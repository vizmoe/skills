# 封面

外部封面候选的身份与采用门槛按[检索与匹配规则](sources.md#名称与艺人检索及置信度门槛)核验。

候选来源优先级依次为：已核验的原内嵌正面封面、MusicBrainz / Cover Art Archive、Apple Music / iTunes。只有上述网络来源及原内嵌图均未获得可靠且高质量的合格正面封面时，才进入[本地扫图兜底裁切提取](#本地扫图兜底裁切提取封面)分支；未穷尽规定网络来源前，本地外置图片仅作发行核对线索。用户明确指定使用的封面按本次授权处理，仍核验发行身份与比例。文件名 `cover` / `front` 或存放在专辑旁不能单独证明来源及身份。

## 版次与采用范围

在像素比较前，逐候选保存完整版次对照。标题、日期和总曲数都相同也不足以确认正面封面；不能把同名再发行、数字版或另一地区版的图片自动套用到本地 CD。

| 对照项 | 记录与判定 |
| --- | --- |
| 有序曲目 | 按原媒介/碟号/曲号逐项对照标题、艺人及可用时长，附赠部分单独映射；不能只比较无序标题集合或抽样通过就忽略其它曲序冲突 |
| 目录号与版次 | 核对适用的目录号、条码、初回/通常/限定/再发行标识及日期，区分父产品编号与独立 CD 编号；缺少版次区分证据时保持未知 |
| 媒介与随附关系 | 明确数字发行、CD 或带特典 CD 的父套装；保留完整发行证据，不能因音乐处理排除了 DVD/BD 就丢掉版次差异 |
| 来源地区 | 保存来源 URL/发行 ID、商店地区及其与目标版次的对应依据；商店地区本身不证明发行国家或图片版本 |

任何关键差异未解释时，候选只作线索，记录排除原因并继续查询；例如 Daisy 情景中同名、同日期、同曲数但曲序不同的候选不能过关。各项标注已确认、未知或不适用及证据，不能把没有提供目录号或曲序当成“相同”。只有确认同一发行且无未解版次歧义的正面图才进入下列几何与质量筛选。

## 正面图片校验

仅采用已可靠确认属于同一发行的正面封面，并按以下顺序筛选：

1. **检查真实尺寸与比例。** 使用 [cover-info](tools.md#封面尺寸预检) 完整解码图片（含 EXIF 方向矫正）并读取宽 `W`、高 `H`，均须大于零；近似正方形定义为 `max(W, H) / min(W, H) ≤ 1.40`，即长边最多比短边长 40%。原内嵌图与下载图执行同一门槛，不凭文件名或 URL 中的尺寸推定合格。
2. **保持原始比例。** 如需缩放，等比例缩放并复核输出；禁止通过拉伸、补边或对单面非方形主图强行截断来使不合格图片过关，改查同一发行的合格正面封面；仅在[本地扫图兜底裁切提取](#本地扫图兜底裁切提取封面)分支中，允许沿实体封套/小册子展开图的真实正面边界裁切出正面画幅。
3. **比较合格候选。** 先满足发行身份与比例要求，再优先选择像素数（`W × H`）较高者；像素数相同时优先文件体积较大者。记录来源、实际宽高、比例及选择或排除原因。

只选一张，格式支持时嵌入每轨；写入后读回核对唯一正面封面及实际尺寸、比例。最终成品不保留外置封面；候选副本可暂存于受控临时位置，嵌入并校验、归档必要证据后按[清理规则](delivery.md#清理)处置。原始外置扫图、小册子与 sidecar 的清理或保留条件按[非音乐 sidecar 条件清理规则](delivery.md#非音乐-sidecar-条件清理规则)执行。

支持嵌入封面且网络来源、原内嵌图与本地扫图均无可靠且比例合格的正面图时，标记 `REVIEW_REQUIRED` 并说明缺失、身份不明或比例超限；保留可恢复的源文件与原封面，不标记 `COMPLETED`，不进入破坏性清理。

## 本地扫图兜底裁切提取封面

当且仅当 MusicBrainz / Cover Art Archive 与 Apple Music / iTunes 均未返回可靠且高质量的同版次正面封面（且无合格原内嵌封面）时，检查该发行随附的本地扫图与小册子图片（`.jpg`、`.jpeg`、`.png`、`.tif`、`.tiff`、`.webp`、`.bmp`、`.gif`），尝试非破坏性提取正面封面：

1. **先凭实体扫图确认发行身份。** 核对扫图集合中册页、侧标（obi）、封底或碟面上的标题、艺人、目录号、条码与曲目表，确认属于当前目标发行；不能仅凭目录位置或 `cover`/`front` 文件名采用图片。
2. **只选取真正的正面封套画面。** 排除光盘盘面（disc label）、封底（back tray）、单条侧标（spine/obi）、纯歌词页、内页插图或归属不明图片。
3. **按版面提取与非破坏性裁切。**
   - 若扫图本身已是独立正面封面且通过 [cover-info](tools.md#封面尺寸预检) 完整解码与 `max(W, H) * 5 <= min(W, H) * 7` 检查，直接复制到当前专辑 staging 目录作为候选，记 `cover_source: "local_scan_front"`。
   - 若扫图为多面展开图（如 2:1 正反面小册子对开页、三折 digipak、带侧标或白边扫描框的实体封套），先用只读 `library_guard.py cover-info --crop LEFT,TOP,RIGHT,BOTTOM`（基于 EXIF 方向矫正后的像素坐标）预检真实正面画幅边界与比例，再将裁切后的正面图输出到 `albums/<album_id>/staging/`，记 `cover_source: "local_scan_crop"`。**禁止原地覆写或直接裁切原始扫图，禁止拉伸、补边或为凑比例破坏单面画幅。**
4. **读回校验与溯源留痕。** 裁切/提取后的候选图须再次通过 `cover-info` 完整解码、尺寸与比例校验；嵌入音频并读回确认后，在 `details.assessment.cover` 记录 `cover_source`（`local_scan_front` 或 `local_scan_crop`）、`online_cover_found: false`、源扫图相对路径、源 SHA-256、裁切矩形 `[left, top, right, bottom]`（如适用）及最终宽高与比例。
5. **联动 sidecar 保留规则。** 通过本地扫图兜底获得合格正面封面后，可满足成品内嵌封面要求并正常发布、清空专辑 staging；但因未取得高质量网络封面，按[非音乐 sidecar 条件清理规则](delivery.md#非音乐-sidecar-条件清理规则)须保留该专辑的原始扫图、CUE、播放列表与文本 sidecar，不得清理。

## 父产品或套装图片

可在来源材料中另行保留官方父产品/套装图，类型明确记为 `parent_package`，独立 CD 的合格正面记为 `release_front`。本分支不把官方套装图加入默认独立 CD 正面候选，也不把父套装确认为 CD 的具体封面版本。

采用父套装材料前，须从发行方官方目录同时证明：具体父产品及目录号/媒介/版次、该版确实随附目标 CD、CD 的曲目或其它可靠身份对应，以及图片确属该父产品。仅同一动画名称、同页列出多个版本或图片视觉相似均不足。将图片原始 URL、官方目录 URL/快照、父目录号、随附关系、目标 CD 映射、图片哈希和实际尺寸保存在 `details.assessment.cover` 的证据记录，并在报告显式显示“父产品/套装图片，非独立 CD 正面”。

这类参考图归档到受保护状态位置的 `preserved/<album_id>/artwork/`，保留来源映射，不混入音轨成品目录或自动嵌入为 front cover。若用户明确要求把它用于展示，沿用既有封面例外授权；仍核验真实尺寸、完整解码及比例，记录实际原生图片类型/描述与读回结果，能表达时使用非正面类型及套装说明。容器无法可靠区分用途时仅保留证据/报告，不把它伪装成独立 CD 正面。不要发明 `SOURCE` 等白名单外文本标签，父目录号也不自动写成 CD 的 CATALOGNUMBER。

父套装参考图不使标准正面封面检查变为通过；没有合格 release_front 仍按[报告分类](reporting.md)列为缺封面，保持已确认录音与专辑上下文。用户明确选择的展示例外只说明本次采用范围，不修改默认完成门槛。
