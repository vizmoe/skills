# 复核、清理与交付

## 每张专辑复核清单

分阶段读取下列清单。检查点只记录可观察结果，具体判定按对应规则；适用项全部通过并有证据才进入下一阶段，范围外项目注明理由。[安全部分整理](sources.md#分维度采用与安全部分整理)可先交付已核验副本并继续剩余工作；下面完整成品的门槛不用于阻断副本中已有证据的曲目标签补全。

### 发布前阻断检查

- [ ] 所采用事实在各自层级通过身份与置信度核验，双源查询及逐轨范围有记录；录音、成员关系与专辑上下文分别判断。[来源门槛](sources.md#名称与艺人检索及置信度门槛)、[分维度规则](sources.md#分维度采用与安全部分整理)
- [ ] 实际 codec、完整解码及适用的转换校验通过。[音频格式](audio.md#音频格式)、[转码校验](audio.md#转码校验)
- [ ] 适用必填项齐全或符合[缺失例外](metadata-whitelist.md#可靠信息缺失例外)且已记录；原生读回与拟写字段、值、多值顺序一致，白名单校验通过。[字段与存储](metadata-whitelist.md)、[读回流程](metadata.md#白名单化流程)
- [ ] 标题、专辑及艺人变更都有保留或规范化依据；特殊署名已逐项核验。[内嵌值优先](metadata.md#当前内嵌元数据优先)、[后缀](metadata.md#apple-发行类型后缀清理)、[艺人](artists.md)
- [ ] 唯一正面封面身份、解码、尺寸、比例及嵌入读回通过；若走本地扫图裁切兜底，已保存源扫图哈希与裁切坐标。[封面](cover.md)
- [ ] 成品碟轨统计和路径来自读回标签；整张路径计划无冲突，源可恢复，发布操作拒绝覆盖。[计数](metadata-whitelist.md#轨号碟号与日期)、[路径](paths.md)、[事务](execution.md#事务与恢复)

### 清理前完整复核

先核对发布后的全部实际文件及指纹与上述证据一致，再完成适用分支：

- [ ] 实际写入的发行国家、受控流派、日期及选填值各有对应来源，层级与所选版本一致；允许的缺失有查询证据和原因。[白名单](metadata-whitelist.md)、[流派](metadata.md#genre-受控词表)、[来源优先级](sources.md#来源优先级)
- [ ] 个人姓名、实体边界、角色及多值顺序在标签和路径中一致。[日文姓名](artists.md#日本艺人姓名空格规范化强制)、[连接符](artists.md#musicbrainz-艺人连接符处理强制)
- [ ] 合辑署名、角色/CV、客席及声库适用分支各有实体和角色证据。[合辑署名](artists.md#various-artists)、[CV](artists.md#角色歌曲与-cv-署名)、[客席](artists.md#featuring-与客席艺人)、[声库](artists.md#vocaloid-与歌声合成器)
- [ ] 人员、作品字段及输入别名均映射到规定存储，成对 credit 可逐项对照。[credit](metadata-whitelist.md#表演类-credit-成对规则)、[输入别名](metadata-whitelist.md#输入别名与最终键)
- [ ] 被排除介质、未匹配曲目及含未替代内容的压缩包均已独立登记。[介质](audio.md#dvd-与-bd-碟排除与计数)、[部分匹配](sources.md#完整匹配与部分匹配)
- [ ] 来源组已覆盖侧车/内嵌 CUE、全部媒介及附赠音频；分轨输出都有后续匹配结果及实际去向，未执行或读取失败与有效零结果分开。[发现范围](sources.md#整套发行与附赠内容发现)
- [ ] 初始扫描内每个源文件都有成品、删除、归档保留或原位保留去向；新增或变化文件已重新核对，清理清单无未证明归属项。[清理](#清理)

### 清理后检查

- [ ] 成品目录符合[目标结构](paths.md#目标结构)，音轨数量和指纹仍与发布记录一致。
- [ ] 实际删除、归档及原位保留逐项对账，归档副本可读取且 SHA-256 一致；源目录残留与空目录处置都有结果或具体原因。
- [ ] 最终恢复快照覆盖所有仍存在的源、成品及保留数据，已删除路径可核对；报告链接到实际产物和记录。[跨运行记录](tools.md#跨运行记录格式)
- [ ] 所有改写过的现存成品均以最终哈希对账，操作映射和历史修订可追溯；不只检查已移除源路径。不能解释的哈希差异、遗漏和重复目标阻断“审计全部通过”的报告。[成品改写](execution.md#成品改写与历史修订)
- [ ] 运行 [staging-audit](tools.md#暂存与残留审计)（传入全部 `--state-dir`），确认无孤立 staging/quarantine 文件、无未清理临时/PCM 缓冲、无空 staging 目录且无未登记的 `.staging` 旁路目录；`COMPLETED` 专辑不再持有 `role: "staging"` 文件，恢复副本仅属于未终结或阻断专辑。[Staging 退场](execution.md#staging-生命周期与退场)

## 清理

清理在发布成功且全张适用复核通过后进行。先核验[文件角色和原始文件策略](execution.md#文件角色与可选产物)：下表仅规定可处置工作、衍生、待复核副本及缓存的内容条件，不授予原始文件删除权限。原始文件默认原位保留，包括原始图片、压缩包与 sidecar；独立策略明确覆盖的操作才可继续。运行期间在专辑 staging 中产生的暂存源副本、整盘中间转换、分轨中间体、解码缓冲和改标签回滚备份属于可回收工作/衍生副本，须按[Staging 退场规则](execution.md#staging-生命周期与退场)在专辑 `COMPLETED` 时清空，不因保留原始源盘而永久滞留。执行前逐文件登记所属专辑、角色、当前 SHA-256、处置和依据；执行时再次比对。文件变化、归属不明或未登记时原位保留。**扩展名本身不授权删除。**

工作副本的删除须按[隔离、对账与恢复协议](cleanup.md)先保存清单和等价证据；所有相关快照、报告及 manifest 检查通过后才最终移除隔离副本。对实际文件续做，不通过还原 JSON 假装撤销已发生的删除。

| 对象 | 处置条件与结果 |
| --- | --- |
| 工作 WAV、AIFF、APE、旧 FLAC、整轨镜像及其它已替代音频副本 | 仅在替代品全部校验通过且映射完整时进入清理 |
| CUE、`.m3u` / `.m3u8`、外置封面、扫图、booklet、LOG、随附文本/校验文件及已排除的 DVD / BD / 视频容器 | 所属音乐全部完成、恢复与来源证据已入记录后，按[非音乐 sidecar 条件清理规则](#非音乐-sidecar-条件清理规则)判定：已核验高质量网络封面与可靠网络元数据时清理（用户明确保留的资料除外），否则保留；已完全替代的音乐压缩包或经成员核验 100% 仅含被排除 DVD / BD 介质的纯特典压缩包可在音乐全部完成后清理 |
| 封面候选缓存与临时解压文件 | 嵌入校验并归档必要证据后随专辑 staging 退场清理 |
| `Thumbs.db`、`desktop.ini`、`.DS_Store` | 属于当前可清理工作目录且逐项登记时可删除 |
| 用户明确保留的资料、含跨专辑引用或有独立归档需求的非音乐 sidecar 副本 | 归档到受保护状态位置的 `preserved/<album_id>/<原根目录相对路径>` 或原位保留；归档须独占创建副本并验证 SHA-256，保留原路径映射。目标已占用即保留待处理副本并复核 |
| 未识别、不可读、归属不明、符号链接及含未替代音乐或未知成员的压缩包 | 原位保留，逐项报告原因与路径；继续核验后再决定，音乐完成不解除这些保留条件 |

阻断性的身份、必填信息、CUE、转换、封面、读回或路径问题出现时，保留恢复所需全部源数据及原封面，暂停该专辑破坏性清理。已确认并妥善处理的部分匹配本身不阻断清理。含任何未替代介质或未知成员的压缩包保持原样。

### 非音乐 sidecar 条件清理规则

在已授权的清理/迁移范围内，且专辑音频已全部通过校验并达 `COMPLETED` 时，非音乐 sidecar 的默认去向取决于是否同时取得了**高质量网络正面封面**（来自 MusicBrainz / Cover Art Archive 或 Apple Music / iTunes 的同版次合格正面封面，`cover_source: "online"`）与**可靠网络元数据**（双源核验且无未解阻断项）：

- **同时找到高质量网络封面与可靠网络元数据**（`online_cover_verified: true` 且 `online_metadata_verified: true`）：清理该专辑专属的 `.cue`、`.m3u` / `.m3u8`、扫图/小册子图片、随附日志/文本校验文件，以及已排除的 DVD / BD 镜像结构与视频容器（若单独视频容器含附赠音轨，须先确认音轨已归档或确属排除介质；纯特典 DVD / BD 压缩包须先核验全部成员确为被排除介质后再清理），并在清理清单中逐文件记录路径与 SHA-256；随后对因此变空的扫图/碟片/专辑子目录按[空目录规则](#空目录)执行 `rmdir`。用户明确要求保留的特定资料仍以用户要求优先。
- **未找到高质量网络封面或缺少可靠网络元数据**（包括网络无封面而改由[本地扫图兜底裁切提取](cover.md#本地扫图兜底裁切提取封面)得到 `local_scan_front` / `local_scan_crop` 封面的情况）：**必须保留**相关 `.cue`、`.m3u` / `.m3u8`、扫图、随附文本/日志与随附 DVD / BD / 视频容器作为原始依据与恢复来源，不得清理。
- **范围边界**：本表仅适用于已核验归属的专辑非音乐 sidecar 与已排除的 DVD / BD / 视频容器，绝不授权仅凭扩展名删除音频文件、未核验成员的压缩包、符号链接、受保护状态目录内文件或跨专辑共享文件。下表同时供只读 [check-sidecars](tools.md#非音乐-sidecar-清理预检) 解析执行，代码不另存第二份规则表：

| Sidecar 类别 | 扩展名集合 | 高质量网络封面与元数据已核验 | 缺少高质量网络封面或元数据（含本地扫图兜底） |
| --- | --- | --- | --- |
| `cue` | `.cue` | `clean` | `preserve` |
| `playlist` | `.m3u, .m3u8` | `clean` | `preserve` |
| `scan_image` | `.jpg, .jpeg, .png, .tif, .tiff, .webp, .bmp, .gif` | `clean` | `preserve` |
| `companion_text` | `.log, .txt, .nfo, .md5, .sfv, .accurip` | `clean` | `preserve` |
| `video_disc_media` | `.iso, .mds, .mdf, .vob, .ifo, .bup, .bdmv, .clpi, .mpls, .m2ts, .mp4, .mkv, .avi, .mov, .m4v, .ts, .wmv` | `clean` | `preserve` |

### 空目录

逐文件处置结束后，按深度从深到浅核对计划内的可清理工作专辑目录及其子目录。原始目录默认保留，独立策略未覆盖时不纳入候选。仅对当时确实为空、归属明确、处于根目录内且不经过链接的目录执行 `rmdir`。根目录、状态目录、其它专辑目录及非空目录保留；竞态新增内容导致移除失败时记录残留。每个候选记录已移除或保留原因，不递归强删，不向上扩展到未列入计划的父目录。

## 状态与最终报告

以下是状态语义的唯一事实来源。执行结果、匹配范围和数据处置分别记录；例如成功整理的部分匹配专辑可同时有 `COMPLETED`、`PARTIAL_MATCH` 及归档资料的 `PRESERVED`。

| 维度 | 状态 | 含义及必报内容 |
| --- | --- | --- |
| 执行 | `COMPLETED` | 授权范围内适用校验、发布和清理全部结束；列实际最终路径。未执行的部分范围明确注明，不能据此声称全专辑完成 |
| 执行 | `SKIPPED` | 明确排除或不处理的内容，例如非音乐、DVD / BD、加密包；列范围和原因 |
| 执行 | `REVIEW_REQUIRED` | 证据、规则前提、历史归属或清理去向尚有阻断项；列缺失信息及恢复位置 |
| 执行 | `FAILED` | 实际解压、分轨、转码、标签、发布、清理或校验操作失败；列操作、错误及已产出结果 |
| 匹配 | `FULL` | 发行身份已确认，本地与公开曲目表完全一致；列匹配范围及证据 |
| 匹配 | `PARTIAL_MATCH` | 已确认部分录音、字段或专辑上下文，精确成员关系或完整曲目表仍不全对应；分别列已确认范围、本地额外/缺失曲目及未知维度 |
| 匹配 | `UNCONFIRMED` | 尚无可可靠采用的录音身份、曲目字段或专辑上下文；列已查来源及缺口，不覆盖已有独立确认维度 |
| 处置 | `PRESERVED` | 刻意归档或原位保留的数据；列原路径、现路径、指纹及原因，不等同于执行失败 |

本表是机器记录的完整取值范围，[辅助工具](tools.md#跨运行记录格式)直接按此表校验；未终结的执行结果记为 null。报告包含本轮处理、复用、跳过、待复核、失败和剩余数量，逐专辑实际状态与理由，非阻断性缺失字段及其查询证据、原因，以及删除、归档、原位残留、空目录各自的数量和路径。只写“保留源文件位置”不满足逐项对账要求。

处置统计按原始文件、工作副本、分轨/转码衍生文件、待复核副本和缓存分别列出保留与清理数量、路径、理由及校验证据；默认保留原始文件是已落实的策略，不列为失败或未完成清理。另报 LRC 生成开关及实际新建数量，明确关闭时必须为零。

生成最终报告时按[分类与最新结果归并](reporting.md)区分未识别音频、部分匹配、缺封面、CUE、证据附件及已完成副本；合并最新发布/清理结果后才生成待复核音频列表，不生成空 review 组或空快照。
