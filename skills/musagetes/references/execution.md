# 执行、记录与恢复

## 运行边界与记录

音乐根目录来自用户授权，记录其绝对实际路径。根目录为符号链接时，将解析后的真实路径明确用作后续 `--root`；库内链接原位保留。多个根目录按用户给定顺序分别处理，计划中的路径本身不授予权限。

状态写入根目录内独占创建的 `.musagetes/runs/<run_id>/`，安装目录保持只读。若 `.musagetes` 是链接或已有无法确认归属的用户数据，保留原位置，选择并登记另一个获准的状态目录；每次调用工具都通过 `--state-dir` 传入所有替代位置。状态目录放在成品专辑之外；读取 [tools.md](tools.md) 了解保护及记录格式。

每次运行保存 `run.json`（根目录、时间、模式、当前 `metadata.version`、工具版本、用户例外、状态位置、批量参数），以及以下资料：

| 资料 | 必须覆盖的内容 |
| --- | --- |
| 扫描快照 | 相对路径、类型、大小、时间、分组依据；拟修改或清理文件的 SHA-256；原生字段、多值顺序、封面和未知标签 |
| 来源证据 | 按 [sources.md](sources.md) 记录双源查询、URL / ID、地区、介质、逐轨映射、置信度和采用范围 |
| 专辑计划 | 稳定 `album_id`、计划摘要、源到成品映射、codec 操作、标签前后值及理由、字段删除集、封面、碟号映射、目标和残留物处置 |
| 专辑日志 | `albums/<album_id>/operations.jsonl` 记录每次操作开始、结束、命令退出结果、实际路径、指纹及校验证据；每张专辑独立记录 |
| 恢复快照 | `albums/<album_id>/events/<sequence>.json`，按[跨运行记录格式](tools.md#跨运行记录格式)保存完整剩余文件清单及阶段 |
| 交付 | 最终路径、状态、匹配范围、阻断项、逐文件保留或清理结果，见 [delivery.md](delivery.md) |

大文件和网页用摘要与引用，避免重复嵌入日志。来源查询只发送识别音乐所需信息。纯审计可直接输出工具结果；需要落盘的报告只写到获准位置。调用 Python 加 `-B`，避免在安装目录产生缓存。

## 文件角色与可选产物

扫描时按来源链给每个文件分配稳定 ID 和下列角色，并记录原路径、当前路径、指纹及产生它的操作；不凭目录名、扩展名或相同字节推定可删除性。

| 角色 | 边界 |
| --- | --- |
| `original` | 用户输入的原始文件，包括音频、整轨、压缩包、CUE、图片与 sidecar；默认原位保留，不改写或迁走 |
| `working` | 已有可恢复原始文件的独立工作副本；归属与复制证据明确后才可按清理协议处置 |
| `derived` | 本次分轨、转码等产生的文件；未验证完整替代前保留，发布后的成品不是待删副本 |
| `review` | 为待核验项目制作的副本；即使位于 review 目录，唯一音频或未替代内容仍须保留 |
| `cache` | 可重建的查询响应、封面候选或临时资料；被日志引用的必要证据先归档，不能随清理丢失 |

这些是操作计划的来源角色，写入 `details.file_roles` 或其引用；不替换[历史快照的存储角色](tools.md#跨运行记录格式)。一个文件移动后沿用 ID，独立副本另有 ID 与 `derived_from` 映射。已存在但来源链不明的文件按原始文件保护，不自动认定为工作副本。

`run.json` 记录 `original_policy: preserve`。原始文件删除或迁移须有独立、明确的用户策略，列出获准路径、操作和已有会话授权依据；普通“整理”或成品通过校验不等于此策略。已有明确授权直接沿用，缺少策略时保留原始文件并继续处理副本，无需为默认保留阻断整理。目录原样保留同样适用；不能用“归档 sidecar”间接移除原始资料。

`generate_lrc` 默认关闭，只有用户单独启用才生成；明确关闭时所有分支均不调用 LRC 生成器，交付记录新生成数量为零。已有 LRC 与可信 `LYRICS` 按原始资料和标签规则保留，开关不授权删除歌词。启用后仍须有可靠歌词与时间轴，缺少时不虚构；可选产物的去向与来源记入计划，不能改变成品目录仅含音轨的默认结构。

## 跨运行发现与续做

每次开始（包括未明确说“恢复”的新运行）先枚举所有登记状态位置下的既有 `runs/`，运行 [history](tools.md#跨运行记录格式) 核对最新专辑快照，再与本轮 inventory 对账。**历史快照集合是跨运行账本，不另维护可漂移的完成缓存。** 新 run_id 沿用已识别专辑的 album_id；只有确定是新事务时才生成新 ID。

- `sequence` 按同一 album_id 跨运行严格递增，用最大序号选择最新快照；使用完整快照，旧记录保持不可变。时间和目录名不决定先后或完成状态。
- 最新记录完整、全部当前指纹相同、应已移除路径仍不存在、skill 版本一致时，才成为复用候选；还需核对计划、原校验证据、当前专辑新增文件及本次范围。目录名符合模板或终态字符串本身都不充分。
- 版本变化触发领域复核；文件变化触发重新扫描和计划。损坏记录、重复序号、未知历史格式或无法证明归属时保留现状并复核，不能回退到更早的完成记录来跳过。
- 旧 runs 中仅有散装报告或旧 state.json 时，先核对其根目录、文件指纹和事务归属，再显式迁移为有原记录引用的新快照；无法证明的专辑保持待复核。原历史资料保留。
- 中断或部分发布优先恢复：核对源、staging、已发布输出及操作日志，只继续或回退能证明属于该事务且指纹未变的项目。其它文件一旦介入，停止对应操作并列出差异。

每张专辑同时只允许一个执行者。快照通过写临时文件、校验完整 JSON、独占发布新序号的方式保存；部分写入或无快照的操作以日志和当前文件重新核验。只读 helper 不负责加锁或写状态。

### 成品改写与历史修订

标签、封面、转码、分轨、移动或去重都会触发文件与历史对账，包括路径没有变化的成品。每项操作在日志记录输入路径/旧 SHA-256、输出路径/全部写入结束后的 SHA-256、操作类型和验证证据；在最新完整快照的 `details.operations` 保存这些映射或日志引用，并以 `details.previous_record` 引用上一快照。保留仍存在的所有原始、成品及恢复副本，不只核对 `removed_paths`。

发现旧快照的成品哈希过期时，先查操作日志、音频等价、原生标签/封面读回与实际路径；能解释差异才追加新 sequence 的完整修订快照。旧事件、旧哈希与旧报告不覆盖、不批量“修正”。不能解释的变化、缺失或重复目标保持阻断，不能只用当前哈希覆盖账本来让审计变绿。修订后重新跑 history 并与 inventory、清理 manifest 及报告对账；直到全部实际成品一致才声称最终报告通过。版本复核也使用新快照留痕。

## 批量协议

默认每批 `batch_size=10` 张专辑。范围、`limit`、批大小和失败阈值记入 run.json；这些是执行计划参数，不是只读 helper 的命令行选项。

1. 先对账历史，再将未完成事务排在前面；其余按来源相对路径的 NFC + casefold 排序，同键按原路径排序。记录初始队列，以免移动后顺序漂移。
2. 已完成且通过本轮复用核验的专辑记为无需变更，不占 `limit`；其余每张进入执行即占一次，包含失败和待复核。用户未指定 limit 时覆盖全部授权范围。一次运行同一专辑最多入队一次。
3. 每项文件操作落专辑日志，每次阶段变化、清理完成或失败落恢复快照；完成一张就更新本轮进度。每批结束或距上次汇报 60 秒时汇报完成、复用、待复核、失败、剩余数量及当前阻断原因。
4. 批结束是检查点；在授权范围内继续下一批。达到用户指定 limit 才结束本轮，并报告剩余队列和恢复位置。
5. 默认连续 **3 张实际执行失败** 后暂停该根目录的后续写操作，保存记录并向用户报告共同错误和可选下一步；可继续只读诊断。成功执行一张重置失败计数；复用、跳过、待复核或部分匹配均不增加或重置计数。用户已指定失败处理策略时沿用该策略。

## 事务与恢复

阶段为 `PLANNED → STAGED → VERIFIED → COMMITTED → FINALIZED`，执行结果与匹配状态按 [DELIVERY 的唯一状态词表](delivery.md#状态与最终报告)记录。

1. **PLANNED**：逐文件变更和残留物清单完整，绑定源指纹；阻断项与范围明确。计划或源指纹变化时生成新计划。
2. **STAGED**：在专辑独立 staging 制作副本，源格式不变也复制后再写标签；不使用指向源的硬链接。已有 staging 先核验归属与结果。
3. **VERIFIED**：整张副本通过[发布前阻断检查](delivery.md#发布前阻断检查)，各检查保存证据或不适用理由。
4. **COMMITTED**：从读回标签生成路径，整张预检通过；发布前重检源指纹和目标，使用原子拒绝覆盖的操作。普通 POSIX rename 可能覆盖竞态出现的目标，不能只靠预先 exists()。完成一项立即记录实际输出及指纹。
5. **FINALIZED**：核对发布结果，通过[清理前完整复核](delivery.md#清理前完整复核)后执行逐文件处置，再做[清理后检查](delivery.md#清理后检查)。全流程结束后记录结果及交付；阻断时保留恢复资料。

需要改写但目标等于源路径时按冲突处理。原始文件遵守独立的原始文件策略；仅明确获准迁移的源或可处置工作副本，才可计划先迁出到无冲突恢复位置，核验迁移备份后重新预检空缺目标。清理和回退都只针对清单内、归属明确且指纹未变的文件；不使用目录通配删除或递归删除代替逐项核验。
