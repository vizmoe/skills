# Blog Markdown, Properties and note navigation

## Blog chapters and Properties

```yaml
markdown:
  profile: blog
  chapterMetadata:
    fields: [author, date, source]
    display: byline
```

Blog mode accepts a missing chapter `id` and derives it from the relative path. It inserts an H1 from the required frontmatter `title` in memory when there is none, preserves source files, and uses Astro-compatible GitHub heading IDs, including CJK, punctuation and repeated `-1` suffixes. A synthesized H1 does not shift source heading slugs. In this profile ordinary Markdown images are relative to their chapter; Quillbind figure directives and fonts remain book-root relative. Local assets must already be present. Resolve only the declared local Markdown and assets.

Apply the fixed Properties whitelist. Core `id/title/lang` control the chapter. Optional fields are only `author` (alias `authors`), `date` (alias `pubDate`) and `source`; `fields` may select a subset. Ignore all other keys for EPUBs and reports, including `layout`, `draft`, `tags`, descriptions and private/custom data. Keep output and logs limited to the selected whitelist. An explicitly listed `draft` chapter remains included. Use confirmed book metadata for publication identity and bibliography.

Authors are a string or string list; dates are strings preserved as supplied in chapter head metadata. Prefer `YYYY-MM-DD` dates; ISO timestamps display their written calendar date without timezone conversion. Ambiguous or invalid dates remain in head metadata only. Sources are absolute HTTPS URLs without credentials. Conflicting aliases fail. For the user's Markdown-link source example, use plain `source: https://example.org/post` or quote the whole link as `source: "[原文](https://example.org/post)"`; the unquoted link is invalid YAML. Parse Properties only inside initial `---` frontmatter, not ordinary body text or fenced code.

The default byline is `Author · YYYY-MM-DD`, omitting missing fields and separators. The selected source links the chapter's body title to the original article; the table of contents still links within the book. There are no field labels, icons or separate source labels, and source-only chapters have no empty byline. `display: hidden` retains only head metadata, without a generated byline or title link; `fields: []` ignores optional fields entirely. Keep existing body bylines unless the user authorizes content edits; hide the generated line to avoid duplication. Body styling still follows reader controls.

## Footnotes and jumps

Use `正文[^label]` and a chapter-local `[^label]: 注释正文` definition. For another paragraph or list in the same note, add a blank line and indent four spaces. Named, numeric and Chinese labels work; labels are case-normalized. Repeated references share one note with a distinct return link for each occurrence. Numbering follows first use per chapter. Undefined notes and duplicate definitions fail. Escaped markers and code remain literal.

Use `#heading` or `next.md#heading` for real heading targets; Unicode and percent-encoded fragments are supported. Converted `[1](#fn1)` links require an existing target and do not automatically become footnotes. Recover missing definitions and anchors from source evidence. Astro `.md` conventions are supported within the documented Markdown subset; MDX, raw HTML, TOML frontmatter and arbitrary plugins are not.

EPUB notes carry semantic note/reference roles and bidirectional links for Apple Books and Kindle. Verify each repeated reference returns to its own location. A browser showing end-of-chapter notes does not establish whether a native reader will use a popup. Use [quality.md](quality.md) for release evidence.
