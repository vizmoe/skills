# Authoring guide

The executable authoring contract and examples are maintained in the skill's [authoring reference](../../../skills/quillbind/references/authoring.md), [Markdown syntax reference](../../../skills/quillbind/references/markdown.md) and [blog reference](../../../skills/quillbind/references/blog-markdown.md). Use those references for syntax and field examples; this guide explains source organization. See [Markdown semantics and reading styles](markdown.md) for CommonMark/GFM coverage, CJK emphasis, quotation styling and reader font overrides.

Supported light-novel website URLs use the dedicated [novel collection workflow](novel-sources.md), which produces this same local authoring format and calls the same release pipeline. `init --from` remains the local Markdown preparation command.

`book.yaml` lists chapters in reading order. Neither filesystem traversal nor filenames determine that order. Each chapter starts with YAML frontmatter and parses independently against the [CommonMark 0.31.2 baseline](https://spec.commonmark.org/0.31.2/). The default `quillbind` profile requires an `id` and one H1 matching the frontmatter title. The [blog import profile](blog-markdown.md) accepts Astro-style Markdown without an ID or body H1 and uses GitHub heading slugs. Explicit IDs use `{#id}` after headings. Frontmatter IDs use ASCII letters, digits, underscores and hyphens and start with a letter.

Links between chapter files are relative to the current chapter. Markdown images are relative to the book root in the default profile and to the chapter in the blog profile; figure directives and fonts remain relative to the book root. Local fragments are validated after mapping into EPUB paths; external links must use HTTPS. Footnotes and reference definitions belong to the same chapter. Escape literal reference syntax or put it in inline code. Every fence closes in its own chapter. Raw HTML, unknown directives, MDX and interactive checkboxes produce explicit errors.

Chapter Properties pass through an explicit whitelist. Core `id`, `title` and `lang` control the chapter; optional `author`/`authors` and `date`/`pubDate` provide a compact byline, while `source` links the chapter title to the original article. Other fields are omitted from EPUBs and reports. These values never overwrite book-level authors, publication dates or identifiers. See the blog guide for selection and display settings.

Use semantic Markdown and directives for figures, captions, definitions, notes, ruby, bibliography and page breaks. Tables require `::caption[...]` immediately before the table and render with column headers and `scope`. Figures preserve alt text, and a decorative image must be explicit. Real source page boundaries alone justify numbered markers; reflow and browser pagination do not supply print page numbers. These choices follow [EPUB content and navigation semantics](https://www.w3.org/TR/epub-33/) and [EPUB Accessibility 1.1](https://www.w3.org/TR/epub-a11y-11/).

Examples are original fixtures: `examples/literature` covers Chinese paragraphs, mixed scripts, poetry and cross references; `examples/technical` covers code, mathematics, tables, figures, footnotes, ruby and citations. The automatic layout fixture script adds English prose, Arabic RTL, Japanese vertical text, long identifiers and wide tables.
