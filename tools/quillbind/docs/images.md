# Image preservation and compression

Quillbind accepts JPEG, PNG, GIF and passive SVG for its shared Apple Books/Kindle publication target. It does not impose image byte or pixel limits and never crops, resizes, changes color space, strips metadata, flattens animation or applies lossy encoding. Source files are never overwritten. Display dimensions in CSS control layout without changing source pixels.

The dedicated [novel URL importer](novel-sources.md) adapts a single-frame website WebP image into a separate PNG before entering this pipeline. It retains the downloaded original alongside it and records both hashes and the conversion in `metadata/novel-source.json`. This source adaptation does not change local Markdown builds or existing EPUB repair. Animated WebP is rejected without dropping frames. Website downloads have separate per-request byte limits.

SVG covers and illustrations may use `style="fill:…"` and embedded `<style>` rules. The static-CSS parser permits fills, strokes, fonts and other visual declarations while rejecting resource loading, imports, dynamic expressions and animation. `url()` remains disallowed, including local paint-server references; those resources still require a supported source form. Unsafe CSS produces an SVG-specific diagnostic with the source path. See [security boundaries](security.md).

`build.optimizeImages: true` is the default. Static PNG images keep their format and use level-9 deflate compression, trying all five zlib strategies and choosing the smallest result. Only the IDAT compression stream changes. The engine verifies exact decompressed scanline bytes and exact non-IDAT chunks: bit depth (including 16-bit), palettes, transparency (including invisible RGB), interlacing, ICC, EXIF and text are preserved. This is the highest zlib compression level, not a claim of a globally minimal file. A candidate is used only if the complete file is smaller. Already efficient PNGs, animated PNGs and unknown chunks that depend on image data can retain their original bytes. JPEG, GIF and SVG remain byte-for-byte unchanged. Set `build.optimizeImages: false` to retain all original image bytes.

`dist/reports/images.json` records each source path, source/output SHA-256, byte counts, action, reason and integrity check, including sources deduplicated into the same EPUB resource. SVG remains vector content; active SVG is rejected rather than sanitized or rasterized. Existing EPUB repair preserves its image resources without running new-book optimization.

## Why the shared target does not convert PNG to WebP

The current [EPUB 3.3 core media table](https://www.w3.org/TR/epub-33/#sec-core-media-types) includes WebP. The [Apple Books Asset Guide](https://help.apple.com/itc/booksassetguide/en.lproj/static.html) still specifies JPEG/PNG for interior raster images. The current [Kindle reflowable image guidance](https://kdp.amazon.com/en_US/help/topic/G75V4YX5X8GRGXWV) does not establish universal WebP compatibility. Quillbind therefore requires a supported source format for its shared target; this is a platform policy, not a claim that WebP violates EPUB 3.3. It does not bundle duplicate fallback images merely to claim a smaller book.

WebP also cannot represent every PNG sample losslessly: it uses 8-bit channels, whereas PNG permits 16-bit samples. [Google's WebP FAQ](https://developers.google.com/speed/webp/faq) explains that default lossless encoding may change RGB values in fully transparent pixels. The [cwebp manual](https://developers.google.com/speed/webp/docs/cwebp) requires `-exact` for those values and defaults to dropping metadata. PNG compression avoids these conversions entirely and follows the [PNG compression and chunk model](https://www.w3.org/TR/png-3/).

## Platform checks

`cover.path` is inspected during preflight. A raster cover whose shorter side is below 1400 pixels produces `COVER_RESOLUTION_LOW` with severity `warning`, its source path, actual width and height, and a suggestion to use a higher-resolution original. Exactly 1400 pixels passes; SVG viewports are not treated as raster pixel resolution. The warning appears in `preflight --json`, source-preparation diagnostics and `metadata/preparation.json`, and build `reports/preflight.json` and summary warnings. It never blocks preparation or building, resizes the source, or triggers an approval requirement.

This is a Quillbind authoring default informed by [Apple's marketing-cover recommendation](https://help.apple.com/itc/booksassetguide/en.lproj/static.html), checked on 2026-09-06. Apple distinguishes external store artwork from the interior cover. The 1400-pixel check is not an EPUB conformance requirement or a minimum for ordinary body images. Apple advises using a higher-resolution original rather than enlarging a smaller image to meet the recommendation.

Apple's 5.6-million-pixel interior-image requirement is reported as a warning, never a source rejection or automatic resize. This warning means the output is not assured to satisfy Apple delivery rules. Marketing cover art is a separate asset and is not governed by this interior-image check. GIF raster use, animation and non-RGB color spaces produce specific review findings; CMYK is a format error requiring an author-supplied RGB image. Quillbind retains the source rather than converting colors silently. The metadata must match the actual image media type.

Block images use semantic figures and center within the available line: horizontally in horizontal writing, vertically in vertical writing. Responsive maximum width keeps large images within the text area without stretching smaller images or changing source pixels. Automatic image margins also work with right-to-left text. Centering is Quillbind's layout default; the Apple and Kindle guides do not require all interior images to align left. Figure text, code listings and table captions retain start alignment.

Existing EPUB [repair](repair.md) also centers structurally standalone images, including linked images and figures with separate captions. It preserves the original XHTML structure, authored image dimensions, caption alignment and image bytes. Mixed text and multi-image rows retain their layout; repair does not add new-book image optimization or responsive sizing.

Inline images scale with surrounding text at `1em` and stay in the text flow. Author CSS may use relative image dimensions, including viewport units, without imposing fixed text heights. Captions and alternative text remain text. Browser QA tests the packaged result, including image placement at narrow and wide viewport sizes in both themes. Platform lint is not a claim of testing on vendor devices.

Sources checked: 2026-09-05. Lossless guarantees apply to Quillbind's EPUB; processing by a distribution service is outside this pipeline.
